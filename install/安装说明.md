# 能猫课表 · iPhone 安装包

iPhone 上装 App 只有三种形态：真 App（未签名 IPA + 自己的 Apple ID 签名）、桌面描述文件、Safari 添加到主屏幕。这里三种都给了。

| 包里有什么 | 怎么装 | 适合谁 |
| --- | --- | --- |
| `NengmaoKeBiao-unsigned.ipa`（1.1 MB） | Windows 上用 Sideloadly/AltStore 以本人 Apple ID 签名后安装 | 想要真 App、自动导入和原生提醒 |
| `能猫课表.mobileconfig`（258 KB） | 传进 iPhone → 点开 → 安装描述文件 | 想立刻在桌面看到图标 |
| `nengmao-kebiao-web.zip`（740 KB） | 丢到任意 https 空间 → Safari 打开 → 添加到主屏幕 | 想自己托管、或要在局域网用 |

---

## A. 描述文件（最快，30 秒）

文件：`能猫课表.mobileconfig`，指向已上线的线上版 `https://kebiao-ivoefg6tvfc.qoder.zone/`。

1. 把文件传到 iPhone：微信/QQ 发给自己、AirDrop、或邮件附件都行（微信里点开可能不识别，建议用「文件」App 保存）。
2. 点这个 `.mobileconfig` 文件 → 系统提示“已下载描述文件”。
3. 打开 **设置** → 顶部 **已下载描述文件** → 右上角 **安装** → 输入锁屏密码 → 再点 **安装**。
4. 回到桌面，出现「能猫课表」图标，点开是全屏（没有 Safari 地址栏）。

装错了或想换地址：**设置 → 通用 → VPN与设备管理 → 能猫课表 → 删除描述文件**，再用下面的命令换 URL 重新生成。

```bash
# 换成你自己的地址（例如局域网、或你自己部署的 https）
python install/make_webclip.py --url https://你的域名/ 
```

> 注意：`PayloadContent` 里的 URL 可以是 `http://`。但如果指向**局域网 IP**，iPhone 必须和那台电脑在同一个 Wi-Fi，且电脑上要跑着服务（见 B 的第 3 步）。

## B. PWA 静态包（自己托管）

文件：`nengmao-kebiao-web.zip`，解压后是一个纯静态站点：

```
index.html  manifest.webmanifest  sw.js
app.css  app.js  parser.js  schools-seed.js  theme-c3.css
vendor/xlsx.full.min.js        ← 少了它 .xlsx 导入会报错
icons/icon-192.png  icons/icon-512.png  icons/apple-touch-icon.png  icons/icon.svg
```

**方式 1：丢到现成的静态托管**（Vercel / Netlify / GitHub Pages / 任意对象存储）
上传解压后的**目录内容**（不是整个文件夹套一层），确保 `index.html` 在站点根路径。

**方式 2：局域网自建（同一 Wi-Fi 内测试）**

```bash
# 在解压目录里
python -m http.server 8787
# 电脑的局域网 IP 用 ipconfig 查，例如 192.168.1.5
# iPhone Safari 打开 http://192.168.1.5:8787/
```

然后 iPhone Safari：**分享按钮 → 添加到主屏幕 → 添加**。

> Safari 的「添加到主屏幕」和描述文件效果几乎一样：独立图标、全屏打开、数据存本机。

## C. 能做什么、不能做什么（务必先看）

这两个包跑的是**网页版**，和真正编译出来的 iOS App 差一层原生桥：

> **已实测（2026-11-19）**：线上版有 active Service Worker（缓存名 	imetable-v42），
> 在 WebKit 里断网重载仍能打开、importAutoCourses 仍在。也就是说 A 包装到桌面后**离线可用**，
> 不是必须联网的快捷方式。自检脚本：python install/verify_webclip_target.py。

| 能力 | 网页版（A/B 包） | iOS 工程（需签名编译） |
| --- | --- | --- |
| 导入学校导出的 .xlsx、按周看课表 | ✅ | ✅ |
| 数据只存本机（localStorage） | ✅ | ✅ |
| 桌面图标 + 全屏 | ✅ | ✅ |
| **自动导入**（内嵌登录教务系统抓课表） | ❌ 只能手动导出 xlsx 再导入 | ✅ |
| **原生上课提醒**（本地通知） | ❌ | ✅ |
| **导出 .ics 走系统分享面板** | ❌（Safari 不支持 a[download]） | ✅ |
| 登录态持久化（CookieVault） | ❌ | ✅ |

也就是说：**想先能用，选 A 或 B**；想有自动导入和提醒，必须往下走第三条路。

## D. 真 App：未签名 IPA（已生成）

文件：`NengmaoKeBiao-unsigned.ipa`（1.1 MB，arm64，iOS 15+，Bundle `com.kebiao.app.ios`，版本 1.0 / 构建 1）
SHA-256：`4ebf68f34077c6570662829b4712d471d5e0df813ad736a5e42d49dfc1bbd9c7`
来源：GitHub Actions macOS 构建（`dsgghd/nengmao-kebiao-ios`，run 44433900917），`xcodebuild` 编译通过并已核对 `.app` 内 `Web/`、`Scripts/`、`Info.plist`。

iOS 只安装签名过的 IPA，最后一步必须用**你自己的 Apple ID** 签名。Windows 上不需要 Mac：

1. 安装 [Sideloadly](https://sideloadly.io/)（或 AltStore），并装好 Windows 的 Apple 设备驱动（iTunes 或 Apple Devices）。
2. iPhone 用数据线连电脑，手机上点「信任此电脑」。
3. 把 `NengmaoKeBiao-unsigned.ipa` 拖进 Sideloadly，填 Apple ID，点 Start；需要双重认证时输入验证码。
4. 安装完成后：iPhone → 设置 → 通用 → VPN与设备管理 → 信任你的开发者证书。
5. 打开「能猫课表」。

限制：免费 Apple ID 的签名 **7 天过期**，最多 3 个自签 App；过期后用 Sideloadly 重签一次即可。AltStore 可在同一 Wi-Fi 下自动续签。

没有 Apple ID 或不想签名：用 A 的描述文件 / B 的 PWA；能力差异见 C。

## 附：这次的安装包是怎么生成的

```bash
python install/make_webclip.py                    # 默认指向线上地址
python install/make_webclip.py --url http://192.168.1.5:8787/
python install/make_webclip.py --no-zip           # 只出描述文件
```

描述文件由 `plistlib` 生成（WebClip payload：`com.apple.webClip.managed`，含 512×512 图标、`FullScreen=true`、`Precomposed=true`），
生成后已用 `plistlib` 反解析校验类型与 URL；网页包也已在 WebKit 里跑过一遍：
标题、manifest、`importAutoCourses`、xlsx 库加载、导入落盘全部通过，无 4xx、无 JS 报错。

## 附录：为什么这里造不出 .ipa（实测，不是推脱）

本机（Windows）仍然无法链接 iOS 可执行文件；这次改由 GitHub Actions 的 macOS runner 编译，产出了未签名 IPA。下面是本机尝试的记录，留作说明：

1. **目标文件编出来了**：Windows 的 clang 21 用 -target arm64-apple-ios15.0 + GitHub 上的
   iPhoneOS15.6.sdk（.tbd 链接桩）成功编译出 Mach-O arm64 的 .o，源码是 ios-cross/shell.m
   （不 include 任何 SDK 头文件，运行时用 ObjC 运行时现造 AppDelegate + WKWebView）。
2. **链接不过去**：ld64.lld 明确只实现 macOS——
   error: This version of lld does not support linking for platform iOS。
3. **其他出口都不通**：cctools-port 没有 Windows 版；没有 Docker；WSL 无发行版且
   HypervisorPresent=False（虚拟化未开）；Windows 版 Swift 不带 iOS 标准库。

所以能装的真 App 必须在 macOS（Xcode）或 Linux（theos 的 cctools）上链接。三条收尾路径写在
ios-cross/README.md 第 3 节，其中 B 路线只需要一台 Linux VPS，不需要 Apple 硬件。
